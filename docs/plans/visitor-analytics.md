# GA4 全站访客与访问统计实施计划

## 状态

🔄 进行中。GA4 读取代码、首页底部和后台看板、开发库最小初始化已完成。服务账号已获 GA4 查看者权限，Analytics Data API 已启用；JSON 凭据已写入本机与 VPC 各自的 `.env`。VPC 代理已验证可连接 Google OAuth 和 Data API，待使用服务账号完成 VPC 真实报表联调及页面验收。

## 目标

首页底部展示正式站点的 GA4 累计 PV、UV；后台提供区间概览、趋势和排行。技术设计与配置步骤见[全站访客与访问统计](../designs/features/visitor-analytics.md)。

## 验收清单

- [x] 使用 GA4 `screenPageViews`、`totalUsers` 和 `sessions`，区间 UV 不累加每日 UV。
- [x] 实现服务账号只读认证、域名过滤和 30 分钟服务端缓存。
- [x] 实现首页公开汇总和后台 `analytics:view` 全站权限保护。
- [x] 移除自建采集、访客 Cookie、统计模型和维护任务；保留原有文章级阅读计数。
- [x] 审查空统计表后执行开发库 Prisma 同步、Client 生成及限定范围的配置/权限初始化。
- [x] 更新环境变量、目录、数据库规范与隐私说明。
- [x] GA4 字段、日期、精度与阈值解析测试通过。
- [x] 确认服务账号 GA4 查看者授权并启用 Analytics Data API。
- [x] 将服务账号 JSON 写入 `[mac]` 与 `[vpc]` 各自未提交的 `.env`，限制文件权限为 `0600`。
- [ ] 使用当前环境变量字符串和代理配置运行 `pnpm analytics:verify`，核对真实媒体资源报表。
- [ ] 使用用户手动启动的服务验收首页及后台页面。
- [x] 配置 VPC 运行时凭据及 `GITHUB_PROXY_URL`；两个 Google 域名经代理可达。
- [ ] 部署包含 GA4 OAuth 代理修正的代码并重建容器，再验证真实报表及首页/后台。

服务启动由用户操作。浏览器端 gtag 采集仍受访客网络与拦截设置影响；未拿到真实数据前不把接口不可用解释成零访问。
